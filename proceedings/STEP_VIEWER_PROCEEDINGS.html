Three-Tier Modular Architecture Overview
Clean architectural decoupling between Odoo eCommerce presentation, model hierarchy customizer, and asynchronous backend CAD processing.
System Core

The platform decouples heavy CAD boundary-representation processing from Odoo's primary transactional HTTP workers to ensure system responsiveness and cross-device compatibility:

Website Customizer Modal Full-screen interactive 3D configurator for e-commerce customers with live part-selection drawers.
Customer Quote Portal Dedicated 3D review embedded inside quotation approval views for customer sign-off.
Backend Technical Views Integrated 3D viewport on Product Master, Sale Order Lines, and Purchase Order Lines.

▼ Asynchronous Task Queue & Binary Handshake
Tier 3: Core CAD Ingestion & Pipeline Service cyb_step_file_viewer
MIME Interception & Attachment Service Intercepts raw industrial STEP and STP file uploads across standard Odoo attachment points.
Queue Job Asynchronous Engine Offloads heavy tessellation to dedicated background workers, preventing browser or server freezes.
Server-Side CAD Tessellation Converts heavy boundary representations (B-Rep) to compressed, lightweight WebGL GLB assets.
Modular Strategy: Splitting the suite across three dedicated modules (cyb_step_file_viewer, cyb_product_step_viewer, and product_model_colors) allows the engineering firm to deploy standalone 3D CAD previewing, or optionally enable the full commercial customizer without modifying core Odoo code.
Development Phases & Proceedings
PHASE 1
Foundation & WebGL Engine Feasibility
Initial WebGL canvas integration in Odoo OWL, attachment interception for STEP/STP formats, and tessellation feasibility testing.
50 Hours
▾
Key Engineering Challenges Solved
  1. Browser WebGL Canvas Lifecycle: Engineered safe WebGL context initialization and garbage-collection within Odoo's dynamic OWL dialogs to eliminate memory leaks during multi-tab browsing.
  2. MIME & Attachment Detection: Extended Odoo's native ir.attachment pipeline to intercept and validate raw .step, .stp, and .glb CAD formats.
  3. Feasibility Prototyping: Discovered that client-side tessellation caused severe browser lock-ups on CAD files exceeding 10MB, demonstrating that server-side preprocessing was strictly required.
Engineering Effort Allocation (50 hrs)

    15 hrs
  3. 3 Cross-platform geometry normalization and client alignment
    15 hrs
Milestone Result: Validated that 3D CAD visualization inside Odoo was technically feasible, providing the essential proof-of-concept for the engineering client to define exact commercial specifications.
PHASE 2
Asynchronous Conversion & Queue Architecture
Decoupled heavy CAD conversion using queue_job, OpenCASCADE server-side tessellation, and asset bundle pruning.
40 Hours
▾
Key Engineering Challenges Solved
  1. Non-Blocking Conversion Pipeline: Connected step.file.service with odoo.addons.queue_job to run CAD processing in background threads without blocking user requests.
  2. Server-Side CAD Tessellation: Developed step_to_glb_ocp using OpenCASCADE/CadQuery Python bindings to compress raw CAD solids into lightweight WebGL GLB assets.
  3. Asset Pruning & Optimization: Removed heavy, bundled Three.js libraries (reducing asset payload by over 50,000 lines of code) and replaced them with a clean viewer container.
  4. Photorealistic Engineering Lighting: Added HDR environment maps (citadella, fishermans_bastion, ice_river) for realistic reflections on metallic materials.

Milestone Result: Solved the primary scalability challenge: complex industrial CAD assemblies could now be converted automatically in the background without degrading Odoo's operational speed.
PHASE 3
Deep ERP Workflow Integration & Customer Portal
Dedicated repository extraction, 3D inspection on Sale Orders and Purchase Orders, and secure customer portal preview.
50 Hours

Key Engineering Challenges Solved
  1. Dedicated Repository Extraction: Separated code from the monolithic custom repository into /step_viewer/ for isolated versioning and clean deployment.

PHASE 4
Mesh Extraction, Customizer Engine & Shader Texturing
Binary GLB chunk parsing, dynamic part grouping, WebGL surface shaders, full-image decal wrapping, and state serialization.
90 Hours
▾
Key Engineering Challenges Solved
  1. Binary GLB Chunk Parser: Engineered native unpacker in Python (_extract_names_from_glb_bytes) reading GLB Chunk 0 to extract exact CAD node names without loading entire meshes into RAM.
  2. Dynamic Part Grouping: Implemented part.search and parts.group models with overlap prevention constraints to organize raw CAD parts into customer-facing finish groups.
  3. Custom WebGL Shaders: Wrote custom shader routines executing live metallic sheen, gloss adjustment, and color blending on isolated 3D components.
  4. Full-Image Decal Mapping: Built continuous texture projection algorithms to wrap custom brand graphics and decals cleanly onto selected 3D surfaces.
  5. State Serialization Engine: Implemented state persistence to save custom configurations to product records and automatically re-hydrate the 3D scene on subsequent quote views.
